# Maevelle Documentation Authority

Maevelle's early documents contain valuable domain research, but some also
contain historical MVP, V1, phase, roadmap, deferred-capability, and scoped
implementation language. Those labels no longer limit development.

Use this authority order when documents disagree:

1. the user's current instruction;
2. repository-root [`AGENTS.md`](../AGENTS.md);
3. the [development working policy](development-working-policy.md) and
   [engineering standards](engineering-standards.md);
4. current product-completion evidence and current source/runtime behavior;
5. architecture and domain documents for business rules and design reasoning;
6. initial requirements, old roadmaps, old phases, and historical session notes
   as non-binding context.

The goal is the complete platform. A statement that something was "future,"
"deferred," "out of scope," "post-MVP," or assigned to an old phase is not a
reason to omit it from a current implementation. Re-evaluate it against the
real feature and build it when it belongs to the coherent product workflow.

Historical material is retained because its business reasoning can still be
useful. Superseding its authority avoids losing knowledge while preventing old
scope boundaries from directing new work.
