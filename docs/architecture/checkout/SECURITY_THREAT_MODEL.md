# Checkout threat model

## Phase 02B client execution addendum — 2026-11-04

The [02B report](PHASE_02B_IMPLEMENTATION_REPORT.md) records PARTIAL local acceptance, not a security certification. Real shopper/guest authority, backend quotas/origin checks and current-owner replay remain unchanged. Source and private mutations share one task/revision controller; private payloads are immutable page-memory intents, never storage/URL/telemetry/coordination content. Explicit 409 review, exact uncertain retry, allowlisted writes and response validation protect against silent stale writes or client-created financial truth.

Identity transitions abort/invalidate and clear owner-keyed private state; ignored-abort read/write races pass controller tests. Background suspension hides retained same-owner memory until authorized identity/draft recheck; rejection clears it, network failure keeps it hidden. Explicit guest revocation and draft changes clear prior delivery projection. Browser normal A/B and uncertain-save account switches pass. Exact six-second delayed-response switch timing, actual OS background cloaking, complete browser fault matrix and production ingress remain NOT VERIFIED. Cancellation alone is not an authorization fence; Phase 02A server fencing remains authoritative.

No browser PII persistence was introduced. Unsaved input/exact retry bodies intentionally expire with page/runtime lifetime; reload reads authorized server truth and does not reconstruct/replay them. Real coverage, retention/legal, provider compatibility, human accessibility and inherited Phase 01B release gates remain open. Test control routes exist only in the standalone loopback synthetic fixture, never the deployed API registration. Purchases and production drafts remain disabled.

Scope: browser→Storefront proxy→API→PostgreSQL→outbox/Worker→providers; shopper/account/guest boundaries; Admin financial actions; logs/backups/deployment. Assets: private addresses/contact/order history, commercial commitments, stock, receiving destinations, cash/Finance ledger and conversion attribution. Attacker roles: anonymous bot, malicious shopper, stolen bearer/session, compromised staff, mistaken operator, compromised external provider and compromised infrastructure dependency.

Method: source inspection, not penetration testing. V controls cite audit evidence; R controls below are requirements. Critical = feasible unauthorized money redirection or systemic financial/stock corruption; High = order-integrity loss, PII disclosure or material fraud; Medium = bounded availability/measurement/UX loss. Ratings account for current route gates: dormant fake-placement code is **Critical on activation**, not proof of an active exploited checkout. No permanent-security guarantee or ASVS certification is claimed.

## Phase 02A implemented controls and evidence

Direct API/real PostgreSQL evidence is in [the Phase 02A report](PHASE_02A_IMPLEMENTATION_REPORT.md#8-security-findings-and-residual-risks). T01/T02/T03: shopper-only address access derives tenant/Customer from the live realm, uses existing revocation fencing and partition checks, and denies guest/Admin/foreign UUID/tenant attempts. T04/T05: existing exact Origin/JSON/private-header/quota protections cover new routes; nested allowlists reject coercion/mass assignment, bounded Unicode-safe text is normalized, and parameterized SQL preserves input boundaries. T07: coverage approval is explicit and independent from tariff price; unverified/default/inactive/wrong-country and specifically restricted locations fail safely. Saved edits/removal retain explicit purchase snapshots and require review; exact-key retry, two-tab revisions, fault rollback and lock timeout are exercised.

These controls do not enable purchases, approve a real coverage dataset or establish courier compatibility. Actual proxy/log/role/retention/privacy acceptance, browser delayed-response partition isolation and physical network loss at COMMIT remain unverified. No raw contact body is added to audit, receipt, error or analytics; new address instructions participate in existing Customer anonymization.
